Expand description

A synchronous object store the local VM reads from and (on ExecutionMode::Execute) writes back to.

Implementors only need to provide these four methods; the SDK adapts them to the storage traits the Move execution engine requires.

fn get_object( &self, id: &ObjectId, version: Option<Version>, ) -> Result<Option<Object>, StoreError>

Look up an object by ID. When version is Some, return the object only if it is at exactly that version; when None, return whatever version is held. Ok(None) means the object is absent; an Err means the lookup itself failed (e.g. a networked store’s fetch).

Source

fn get_child_object( &self, parent: &ObjectId, child: &ObjectId, version_upper_bound: Version, ) -> Result<Option<Object>, StoreError>

Resolve a dynamic-field child object owned by parent, returning the child only if its version is <= version_upper_bound.

The networked stores resolve a miss by fetching the child’s latest version and applying this bound as a filter, so a child newer than the bound (historical replay against a pinned older parent, or a subtree under active mutation) reads as absent rather than at an older version.
