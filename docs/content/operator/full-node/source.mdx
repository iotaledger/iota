## 1. Software requirements

- Linux (recommended):
  - For this installer to work, use a Linux distribution with `systemd` and `apt-get`.
  - IOTA recommends and supports Ubuntu or Debian.
  - Building from source also works on macOS (but systemd-related steps won't).
- Rust/cargo stable >1.85 . If needed, [update Rust](https://www.rust-lang.org/tools/install).

<Ports/>


## 2. Run the installer script

In a new directory, (e.g. `mkdir -p $HOME/iota && cd $HOME/iota`), run:

{/* TODO in 6017 change branch last before merging ?? */} 
```shell
bash -i <(curl -sSf https://raw.githubusercontent.com/iotaledger/iota/refs/heads/docs/further-node-operator-docs-improvements/setups/fullnode/systemd/setup.sh)
```

#### Installer script options (via environment variables)
You can override these values when running the script (optional):
{/* TODO in 6017 re-check before PR that these var names are still correct */}
| Env variable | Description | Values | Default Value |
| --- | --- | --- | --- |
| NETWORK | The IOTA public network you want your node to connect to | "testnet", "mainnet", "devnet" | "testnet" |
| CLONE_DIR | Directory to clone a fresh copy of the iota repo into | Path to directory | `$HOME/.cache/iota-clone` |
| NODE_WORKDIR | Directory for all node data (config, binary, DB) | Path to directory | `/opt/iota` |
| CONFIG_DIR | Directory for storing iota-node config files | Path to directory | `/opt/iota/config` |
| BIN_DIR | Directory for the iota-node binary | Path to directory | `/opt/iota/bin` |

:::info
To pass env vars to the installer, declare them as follows, in front of the call to the installer:
```shell
NETWORK="testnet" CLONE_DIR="$HOME/.cache/iota"  bash -i <(curl https://raw.githubusercontent.com/iotaledger/iota.js/master/installer.sh)
```
:::

The installer will perform the following steps:
1. Check your rust toolchain version
2. Install system packages (libraries & other dependencies):  
  `tzdata`, `libprotobuf-dev`, `ca-certificates`, `build-essential`, `libssl-dev`, `libclang-dev`, `libpq-dev`, `pkg-config`, `openssl`, `protobuf-compiler`, `git`, `clang`, `cmake`
3. Clone the [iota repo](https://github.com/iotaledger/iota), set to the right branch for the [network](../../developer/getting-started/connect.mdx#iota-networks) you chose
4. Build the iota-node binary  
  The built binary is located at `/opt/iota/bin/iota-node` (or in `$BIN_DIR` if specified)
5. Create a user called iota, make it own directories for service binary, config, data
6. Create a node config file, download genesis/migration blobs  
  The config and blob files are located at `/opt/iota/config` (or in `$CONFIG_DIR` if specified)
6. Create a systemd service unit file  
  The service definition file is located at `/etc/systemd/system/iota-node.service`
7. Start the service


## 3. Check your installation

Your IOTA node should now be running and connected to the network you chose.

Check that the iota-node service is active and running:
```shell
sudo systemctl status iota-node
```

Check (and follow) the logs:
```shell
journalctl -u iota-node -f
```

If you need to stop the service, you can run `sudo systemctl stop iota-node`

### Reach your node via the RPC endpoint

Your full node serves the read endpoints of the IOTA JSON-RPC API at: <code>{Networks.iota_localnet.jsonRpcUrl}</code>.

Register a new iota client environment with your node's RPC endpoint
```shell
iota client new-env --alias=local --rpc http://127.0.0.1:9000
iota client switch --env local
```
Then query the chain identifier from the RPC endpoint:
```shell
iota client chain-identifier
```

## 4. Updating Your Full node

When IOTA releases a new version, you must update your full node with the release to ensure compatibility with the network it connects to.  
Make sure your node stays on the same network (testnet, mainnet, devnet, ...) it was previously connected to.

Use the following steps to update your full node:

1. Shut down your running full node.
2. Move into the directory for your local `iota` repository and remove `genesis.blob` and `migration.blob` files:

    ```shell
    rm genesis.blob migration.blob
    ```

3. Fetch the latest changes by pulling from the [IOTA repository](https://github.com/iotaledger/iota):
    
    ```shell
    git pull
    ```

4. Download the latest genesis and migration blob:
    <Genesis/>

5. (Optional) Update your `fullnode.yaml` configuration file, if needed.  

    ```bash
    cp setups/fullnode/fullnode-template.yaml fullnode.yaml
    ```

6. Recompile your IOTA full node:

    ```bash
    cargo build --release --bin iota-node
    ```

7. Restart your IOTA full node:

    ```shell
    ./target/release/iota-node --config-path fullnode.yaml
    ```

Your full node restarts on: <code>{Networks.iota_localnet.jsonRpcUrl}</code>.

:::info
If your full node is configured to prune transactions, Archival nodes can help ensure lagging peer nodes don't lose any information. For more information, see [IOTA Archives](../common/archives.mdx).
:::
