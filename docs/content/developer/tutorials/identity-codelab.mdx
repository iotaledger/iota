# IOTA Identity Guided Code-Lab Workshop

In this codelab, we will build a production-ready **University Degree Verification system** using **IOTA Identity** and **Rust**. You will learn how to:

- Create and manage DIDs with helper utilities.
- Issue a **Verifiable Credential (VC)** representing a university degree.
- Package the credential into a **Verifiable Presentation (VP)** from the Holder.
- Verify the VP and its credentials from the Verifier’s perspective.

By the end of this workshop, you’ll have a complete, end-to-end flow demonstrating how **Issuers**, **Holders**, and **Verifiers** interact in a real-world university degree validation scenario — all powered by IOTA Identity.

### Duration Options

60 minutes (fast track)

Before starting this workshop, make sure you have:

    - See [Local Network Setup](https://docs.iota.org/developer/iota-identity/getting-started/local-network-setup)

    - **IOTA Decentralized Identifiers (DIDs)**
    - **IOTA Verifiable Credentials (VCs)** and **IOTA Verifiable Presentations (VPs)**
- Git, if you want to clone the repo.

## The Problem

Today, verifying university degrees is a slow, manual, and often costly hurdle. Employers must contact universities or rely on centralized third-party services, which is costly and prone to fraud. Fake certificates can easily circulate.

## The Opportunity

Universities can issue tamper-proof verifiable credentials that students control using the IOTA Identity Product. Students present these credentials to employers, who can instantly verify them on the IOTA network without intermediaries.

## What You’ll Build in this Workshop

We’ll implement the end-to-end lifecycle of a digital university degree using IOTA Identity:

- **Holder (Student)**: Creates a DID and stores it securely.
- **Issuer (University)**: Issues a **Verifiable Credential (VC)** representing the degree.
- **Holder**: Packages the credential into a **Verifiable Presentation (VP)** and signs it.
- **Verifier (Employer)**: Verifies the authenticity of the presentation and credentials.

All of this will be demonstrated using **Rust CLI applications**, with step-by-step commands you can run on your machine.

## 3. DID Document Creation

```rust
pub async fn create_did_document<K, I, S>(
    identity_client: &IdentityClient<S>,
    storage: &Storage<K, I>,
) -> anyhow::Result<(IotaDocument, String)>
where
    K: identity_storage::JwkStorage,
    I: identity_storage::KeyIdStorage,
    S: Signer<IotaKeySignature> + OptionalSync,
{
    let mut unpublished: IotaDocument = IotaDocument::new(identity_client.network());

    let verification_method_fragment = unpublished
        .generate_method(
            storage,
            JwkMemStore::ED25519_KEY_TYPE,
            JwsAlgorithm::EdDSA,
            None,
            MethodScope::VerificationMethod,
        )
        .await?;

    let document = identity_client
        .publish_did_document(unpublished)
        .with_gas_budget(TEST_GAS_BUDGET)
        .build_and_execute(identity_client)
        .await?
        .output;

    Ok((document, verification_method_fragment))
}
```
This function creates a new `IotaDocument`, adds a verification method (Ed25519 public key), and publishes the DID Document to the IOTA network. It returns the published document and the fragment string.

```rust
pub fn get_stronghold_storage(
    path: Option<PathBuf>,
) -> Result<Storage<StrongholdStorage, StrongholdStorage>, anyhow::Error> {
    let path = path.unwrap_or_else(random_stronghold_path);
    let password = Password::from("secure_password".to_owned());
    let stronghold = StrongholdSecretManager::builder()
        .password(password.clone())
        .build(path.clone())?;
    let stronghold_storage = StrongholdStorage::new(stronghold);
    Ok(Storage::new(
        stronghold_storage.clone(),
        stronghold_storage.clone(),
    ))
}
```

This returns a **StrongholdStorage** instance. It stores keys securely in an encrypted vault file `(.stronghold)`, which is used by the Holder and Issuer to ensure their private keys persist.

## Funded Client

```rust
pub async fn get_funded_client<K, I>(
    storage: &Storage<K, I>,
) -> Result<IdentityClient<StorageSigner<K, I>>, anyhow::Error>
where
    K: JwkStorage,
    I: KeyIdStorage,
{
    let generate = storage
        .key_storage()
        .generate(KeyType::new("Ed25519"), JwsAlgorithm::EdDSA)
        .await?;

    let public_key_jwk = generate
        .jwk
        .to_public()
        .expect("public components should be derivable");

    let signer = StorageSigner::new(storage, generate.key_id, public_key_jwk);
    let sender_address = IotaAddress::from(&Signer::public_key(&signer).await?);

    request_funds(&sender_address).await?;

    let read_only_client = get_read_only_client().await?;
    let identity_client = IdentityClient::new(read_only_client, signer).await?;

    Ok(identity_client)
}
```

This function generates a new Ed25519 key, requests faucet funds for it, and creates a **funded IdentityClient**. This client is necessary for the **Holder** and **Issuer** to publish their DIDs to the ledger.

## Holder Creates a Verifiable Presentation

### What This Enables in the Real World

In our university degree verification use case, the **Holder** (Alice) is the student who received a digital credential (her degree) from the university. To prove her degree to another party (e.g., IOTA Foundation), Alice needs to wrap her credential inside a **Verifiable Presentation (VP)** and sign it with her DID.

This ensures that:

- The credential really belongs to Alice.
- The credential hasn’t been tampered with.
- The presentation is fresh and cannot be replayed by an attacker.

## Short Explanation

The Holder program `(holder.rs)`:

- Creates and stores a Holder DID if one doesn’t exist.
- Accepts a **VC JWT** (degree credential from the Issuer).
- Wraps the VC into a **Verifiable Presentation (VP)**.
- Signs the VP with Holder’s DID and adds a challenge/expiration.
- Saves the signed VP JWT to disk `(vp.jwt)`.

## Codelab: Verifier Validates a Verifiable Presentation

### What This Enables in the Real World

- The Verifier is the third party (e.g., an employer/IOTA).
- Alice presents her Verifiable Presentation (VP) containing her degree credential.
- The Verifier checks:
    - That Alice really signed the VP.
    - That the VC inside is valid and signed by the Issuer (University).
    - That the challenge/nonce matches (to prevent replay attacks).

If all checks pass, the employer can trust Alice’s degree is authentic.

## Short Explanation

The Verifier program (verifier.rs):

1. Loads a VP JWT (provided by the Holder).
2. Extracts the Holder’s DID and resolves it on the IOTA network.
3. Validates the VP against the challenge (nonce).
4. Extracts the embedded VCs and their Issuers.
5. Resolves the Issuers’ DIDs and validates each credential.
6. Confirms that all credentials are valid and belong to the Holder.

```rust
let vp_jwt = Jwt::new(vp_jwt_str.clone());

println!("✅ Loaded VP JWT");
```

- Takes VP JWT from command line argument.
- Wraps it in a Jwt object for processing.

## 3. Set Challenge / Nonce

```rust
let challenge = "challenge-123";
println!("🔍 Using challenge: {}", challenge);
let presentation_verifier_options = JwsVerificationOptions::default().nonce(challenge.to_owned());
```

- Uses the same challenge nonce that the Holder signed.
- Prevents replay attacks.

## 4. Setup Resolver & Resolve Holder DID

```rust
let verifier_client = get_read_only_client().await?;

resolver.attach_iota_handler(verifier_client);

let holder_did: CoreDID = JwtPresentationValidatorUtils::extract_holder(&vp_jwt)?;

let holder_doc: IotaDocument = resolver.resolve(&holder_did).await?;
println!("✅ Resolved holder DID from network: {}", holder_doc.id());
```

- Builds a DID Resolver with IOTA network support.
- Extracts the Holder’s DID from the VP.
- Resolves the Holder’s DID Document from the ledger.

## 5. Validate the VP

```rust
let vp_validation_options = JwtPresentationValidationOptions::default()
    .presentation_verifier_options(presentation_verifier_options);

let decoded_vp: DecodedJwtPresentation<Jwt> = JwtPresentationValidator::with_signature_verifier(EdDSAJwsVerifier::default())
    .validate(&vp_jwt, &holder_doc, &vp_validation_options)?;
```

- Verifies the VP signature with Holder’s DID.
- Confirms the challenge nonce matches.
- Extracts the VP details if validation succeeds.

## 7. Resolve Issuers of Credentials

```rust
let issuers: Vec<CoreDID> = jwt_credentials
    .iter()
    .map(|jwt| identity_iota::credential::JwtCredentialValidatorUtils::extract_issuer_from_jwt(jwt))
    .collect::<Result<Vec<CoreDID>, _>>()?;
println!("🔑 Issuer DIDs: {:?}", issuers);

let issuers_documents: HashMap<CoreDID, IotaDocument> = resolver.resolve_multiple(&issuers).await?;
```

- Extracts Issuer DIDs from each credential.
- Resolves Issuers’ DID Documents from the IOTA network.

## 8. Validate Each Credential

```rust
let credential_validator = JwtCredentialValidator::with_signature_verifier(EdDSAJwsVerifier::default());
let credential_validation_options = JwtCredentialValidationOptions::default()
    .subject_holder_relationship(holder_did.to_url().into(), SubjectHolderRelationship::AlwaysSubject);

for (index, jwt_vc) in jwt_credentials.iter().enumerate() {
    let issuer_doc = &issuers_documents[&issuers[index]];
    let decoded_credential: DecodedJwtCredential<Object> = credential_validator
        .validate::<_, Object>(jwt_vc, issuer_doc, &credential_validation_options, FailFast::FirstError)?;

    let subject_id = decoded_credential
        .credential
        .credential_subject
        .first()
        .and_then(|subj| subj.id.as_ref())
        .map(|id| id.as_str())
        .unwrap_or("unknown");

    println!(
        "✅ Credential [{}]: verified successfully, subject: {}",
        index + 1,
        subject_id
    );
}
```

- For each credential in the VP:
    - Validates the signature using Issuer’s DID.
    - Ensures subject DID matches Holder’s DID.
    - Prints credential subject (e.g., Alice).

End Result: The Verifier confirms that Alice’s presentation is authentic, the degree credential was issued by the university, and that it belongs to Alice.
