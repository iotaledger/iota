# Create and Verify an Event Proof

An event ID contains the emitting transaction digest and the event's transaction-local sequence number. The builder can therefore select the execution without a separate transaction target.

Event proofs carry the transaction's complete event list because the transaction effects commit to that list.

## Prerequisites

- Complete the [Rust](../../getting-started/rust.mdx) or [Wasm](../../getting-started/wasm.mdx) setup.
- Select an active IOTA CLI environment and wallet with funds or faucet access.
- Make sure the JSON-RPC and gRPC endpoints belong to the same network.
- For local or custom networks, set `IOTA_GENESIS_PATH` to an independently trusted genesis blob.

:::important

The example creates a new Locked Notarization transaction. On mainnet, fund the active wallet and set `IOTA_NOTARIZATION_PKG_ID` to an existing Single Notarization Move Package before running it.

:::

## Expected Behavior

- The constructed proof contains one event target and no explicit transaction or object targets.
- The proof carries the complete event data committed to by the transaction effects.
- Successful verification returns the selected event identifier and its authenticated BCS contents.
