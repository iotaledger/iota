# Create and Verify a Multi-Target Proof

A multi-target proof authenticates several targets from the same transaction without duplicating transaction and checkpoint evidence. Every object and event target must belong to the selected transaction.

## Prerequisites

- Complete the [Rust](../../getting-started/rust.mdx) or [Wasm](../../getting-started/wasm.mdx) setup.
- Select an active IOTA CLI environment and wallet with funds or faucet access.
- Make sure the JSON-RPC and gRPC endpoints belong to the same network.
- For local or custom networks, set `IOTA_GENESIS_PATH` to an independently trusted genesis blob.

:::important

The example creates a new Locked Notarization transaction. On mainnet, fund the active wallet and set `IOTA_NOTARIZATION_PKG_ID` to an existing Single Notarization Move Package before running it.

:::

## Expected Behavior

- The constructed proof contains one transaction target, one object target, and one event target from the same execution.
- The object target uses the version recorded in the selected transaction's effects.
- One successful verification authenticates all three targets against the same certified checkpoint.
