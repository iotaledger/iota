# Create and Verify an Object Proof

An object proof starts from an object ID. The builder fetches the latest available version during proof construction, discovers the transaction that produced it, and packages the required evidence.

The discovered transaction supports the object target but does not become an explicit transaction target.

## Prerequisites

- Complete the [Rust](../../getting-started/rust.mdx) or [Wasm](../../getting-started/wasm.mdx) setup.
- Select an active IOTA CLI environment and wallet with funds or faucet access.
- Make sure the JSON-RPC and gRPC endpoints belong to the same network.
- For local or custom networks, set `IOTA_GENESIS_PATH` to an independently trusted genesis blob.

:::important

The example creates a new Locked Notarization transaction. On mainnet, fund the active wallet and set `IOTA_NOTARIZATION_PKG_ID` to an existing Single Notarization Move Package before running it.

:::

## Steps

### 1. Construct the Object Proof

Create an object and request a proof using only its ID. Inspect the resolved target to confirm that the proof contains the object and no explicit transaction or event targets.

The proof authenticates the selected version. It does not prove that the object remains at that version when verification occurs. Deleted and wrapped objects are unsupported.

## Expected Behavior

- The constructed proof contains one object target and no explicit transaction or event targets.
- The builder reports the transaction and exact object version resolved during proof construction as supporting evidence.
- Successful verification returns the authenticated object value; the TypeScript API also exposes its BCS bytes.
