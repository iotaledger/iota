# Reuse a Verifier for Multiple Proofs

A genesis-anchored verifier retains committees authenticated during its lifetime. Reuse one verifier across proofs from the same network to avoid repeating committee resolution.

## Prerequisites

- Complete the [Rust](../../getting-started/rust.mdx) or [Wasm](../../getting-started/wasm.mdx) setup.
- Select an active IOTA CLI environment and wallet with funds or faucet access.
- Make sure the JSON-RPC and gRPC endpoints belong to the same network.
- For local or custom networks, set `IOTA_GENESIS_PATH` to an independently trusted genesis blob.

:::important

The example creates two Locked Notarization transactions. On mainnet, fund the active wallet for both transactions and set `IOTA_NOTARIZATION_PKG_ID` to an existing Single Notarization Move Package before running it.

:::

The default cache remains in memory. Rust applications that need to preserve authenticated committees across process restarts can follow the [Persistent Committee Cache](./advanced/committee-cache.mdx) example.

## Expected Behavior

- The example constructs two independent transaction proofs from the same network.
- One verifier successfully verifies both proofs and returns an authenticated checkpoint sequence number for each one.
- The second verification can reuse committee state authenticated during the first verification instead of starting with a new verifier cache.
