# Create and Verify a Transaction Proof

A transaction proof authenticates a transaction and its effects against a certified checkpoint. The workflow keeps proof construction, transport, and verification separate so the received proof remains untrusted until verification succeeds.

## Prerequisites

- Complete the [Rust](../../getting-started/rust.mdx) or [Wasm](../../getting-started/wasm.mdx) setup.
- Select an active IOTA CLI environment and wallet with funds or faucet access.
- Make sure the JSON-RPC and gRPC endpoints belong to the same network.
- For local or custom networks, set `IOTA_GENESIS_PATH` to an independently trusted genesis blob.

:::important

The example creates a new Locked Notarization transaction. On mainnet, fund the active wallet and set `IOTA_NOTARIZATION_PKG_ID` to an existing Single Notarization Move Package before running it.

:::

## Expected Behavior

- The constructed proof contains the requested transaction target and no object or event targets.
- The proof format version, checkpoint epoch, and transaction target survive the JSON round trip.
- Successful verification returns the requested transaction digest and its authenticated checkpoint sequence number.
