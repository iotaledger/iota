# Define a View Function

This how-to demonstrates how to mark a Move function as a read-only [view function](../explanations/view-functions.mdx) using the `#[view]` attribute. The examples come from a package with three modules: a `leaderboard` that stores player scores, a `registry` that demonstrates returning references, and a generic `vault`.

## Read State From a View

These examples come from the `leaderboard` module, which stores player scores in a shared object.

1. Start from a module with some state to read. Here a shared `Leaderboard` holds a vector of score `Entry` values.
```move file=<rootDir>/examples/move/view_functions/sources/leaderboard.move#L6-L14
```
2. Annotate a `public` function with `#[view]`. A view takes its object by immutable reference (`&Leaderboard`) and returns a value — this one returns the entry count.
```move file=<rootDir>/examples/move/view_functions/sources/leaderboard.move#L31-L35
```
3. A view may take primitives by value alongside immutable references. This one reads the score for a given `player` address.
```move file=<rootDir>/examples/move/view_functions/sources/leaderboard.move#L37-L50
```
4. A view may return a vector of allowed values, such as `vector<u64>`.
```move file=<rootDir>/examples/move/view_functions/sources/leaderboard.move#L52-L63
```
5. A view need not touch on-chain state at all. A pure view takes only values by copy and returns a computed result.
```move file=<rootDir>/examples/move/view_functions/sources/leaderboard.move#L65-L71
```

## Return a Reference From a View

A view may return an **immutable** reference; only mutable references are rejected. This lets a view hand back a borrow into the state it read, instead of a copy. The `registry` module keeps a primary `Setting` inline and stores additional settings as dynamic fields.

2. Return an immutable reference into a field of the object received by reference.

3. Return a reference to a value stored as a dynamic field.

4. Return a tuple that mixes a value and a reference.

## What Not to Annotate

A function that mutates state cannot be a view. `submit_score` takes `&mut Leaderboard` and pushes a new entry, so it is a regular function — adding `#[view]` to it would be a compile error.

```move file=<rootDir>/examples/move/view_functions/sources/leaderboard.move#L24-L29
```

For the full list of what a view function may and may not do, see the [view functions reference](../references/view-functions.mdx).
