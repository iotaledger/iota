## About account abstraction

In an abstract account, transaction authorization logic is implemented in Move instead of relying on
cryptographic signatures alone.  
For multisig accounts, this requires tracking **which transactions are proposed** and **which members have approved them**.

This module defines how transaction proposals and approvals are stored on-chain for a dynamic multisig account.


## What this example shows

This how-to demonstrates the **transaction lifecycle layer** of a dynamic multisig account:

- Storing proposed transaction digests on-chain  
- Recording member approvals for each transaction  
- Preventing duplicate proposals and approvals  
- Removing transactions after execution or cancellation  

This module does not execute transactions itself; it only manages proposal and approval state.

## Verify the result:

After using this transactions module:

- Proposed transactions are represented on-chain by their digests.
- Member approvals are tracked deterministically and transparently.
- Duplicate proposals and approvals are rejected.
- The multisig account can safely evaluate which transactions are eligible for execution.


## Expected Behavior
Transaction proposals and approvals are stored on-chain until execution or removal.
The multisig authenticator relies on this data to decide whether a transaction is authorized.
