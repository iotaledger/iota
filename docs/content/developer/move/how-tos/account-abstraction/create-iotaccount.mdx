This how-to demonstrates how to create an `IOTAccount` with a builder, attach dynamic fields, and rotate the authenticator.
If you want to learn more about the concepts of Account Abstraction, check out the [Account Abstraction Introduction](../../explanations/account-abstraction.mdx).

## Example Code

1. Build and share an `IOTAccount` by creating a temporary builder, attaching an authenticator, and calling [`account::create_account_v1`](../../../references/framework/devnet/iota/account.mdx#function-create_account_v1).
```move file=<rootDir>/examples/move/abstract_iota_accounts/iotaccount/sources/iotaccount.move#L69-L114
```
2. Add an arbitrary dynamic field to the account during build time.

```move file=<rootDir>/examples/move/abstract_iota_accounts/iotaccount/sources/iotaccount.move#L84-L92
```
3. Add, remove, or borrow dynamic fields at runtime (account-only).

```move file=<rootDir>/examples/move/abstract_iota_accounts/iotaccount/sources/iotaccount.move#L115-L162
```
4. Rotate the authenticator function reference (account or admin only).

```move file=<rootDir>/examples/move/abstract_iota_accounts/iotaccount/sources/iotaccount.move#L181-L193
```

## Expected Behavior
- An IOTAccount is created and shared with a valid authenticator function reference attached, and its address can be used as the transaction sender.
- Only the account itself (or the configured admin) can modify dynamic fields or rotate the authenticator; unauthorized transactions are rejected during validation.
