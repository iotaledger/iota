# Create Function Keys Authenticator (Function-Level Delegation with Account Abstraction)

## About Function Keys

Account Abstraction allows an account to define **custom authorization logic** via a Move
`authenticate` function.  

Instead of only checking signatures, the runtime executes this function to decide whether a
transaction sent from the account is allowed.

Function Keys enable per-delegated-key, **function-level authorization** for an account.  
The authenticator implements two flows: **owner** (full-power bypass) and **delegated/function-key** (restricted single-command flow).

### What this example shows

- Create an account with an owner public key and an empty Function Keys store.  
- Grant / revoke per-pubkey function permissions.  
- A dual-flow `authenticate` that:
  - verifies owner signatures (owner bypass), or
  - verifies delegated signatures and enforces one PTB command and function allow-set membership.
- Restrict delegated keys to exactly one allowed Move call per transaction

## Code Outcome

After deploying and using this implementation:
- A shared abstract account is created with a custom authenticator
- The owner can delegate limited permissions to other public keys
- Delegated keys can execute only explicitly allowed Move functions
- The owner retains unrestricted control
- All authorization is enforced on-chain during transaction validation
