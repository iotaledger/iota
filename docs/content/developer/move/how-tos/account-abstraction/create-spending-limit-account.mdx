## About Spending Limit Accounts

Spending Limit Accounts enable programmable spending controls by enforcing a maximum withdrawal amount per transaction. The account maintains a balance reserve (funds available for spending) and validates that withdrawals don't exceed the configured limit. This is useful for allowances, budgets, or controlled fund access scenarios.

The authenticator inspects transaction commands, identifies withdrawal calls, calculates the total amount, and enforces the spending limit.


## What this example shows

- Create a SpendingLimitAccount with a public key, balance reserve, and spending limit.
- Authenticate transactions by verifying signatures and validating withdrawal amounts.
- Withdraw funds from the balance reserve within the spending limit.
- Manage (attach, rotate) spending limits and balance reserves.
- Inspect PTB commands to extract and validate withdrawal operations.

## How it works

### Step 1: Create spending limit account

Create an account with public key authentication, an empty balance reserve, and a spending limit.
```move file=<rootDir>/examples/move/abstract_iota_accounts/spending_limit/sources/spending_limit_account.move#L89-L116
```

**What this does**
- Creates a new SpendingLimitAccount as a shared object.
- Attaches a public key for signature verification.
- Initializes an empty balance reserve to hold withdrawable funds.
- Sets the spending limit (maximum withdrawal per transaction).
- The `limit` parameter defines how much can be withdrawn in a single transaction.


### Step 2: Initialize balance reserve structure

The balance reserve holds funds that can be withdrawn up to the spending limit.
```move file=<rootDir>/examples/move/abstract_iota_accounts/spending_limit/sources/balance_reserve.move#L22-L25
```

**What this does**
- Defines a BalanceReserve struct that wraps a `Balance<T>`.
- Stores the actual funds available for spending.
- Separate from gas funds, dedicated to controlled withdrawals.

### Step 3: Attach balance reserve to account
```move file=<rootDir>/examples/move/abstract_iota_accounts/spending_limit/sources/balance_reserve.move#L54-L59
```

**What this does**
- Adds the balance reserve as a dynamic field on the account's UID.
- Ensures only one balance reserve can be attached (idempotent check).
- Makes the reserve accessible for deposit and withdrawal operations.

### Step 4: Attach spending limit to account
```move file=<rootDir>/examples/move/abstract_iota_accounts/spending_limit/sources/spending_limit_authentication.move#L35-L40
```

**What this does**
- Adds the spending limit as a dynamic field.
- Validates the limit is greater than zero.
- Prevents attaching multiple spending limits to the same account.

### Step 5: Deposit funds to balance reserve

Before withdrawing, the balance reserve must be funded.
```move file=<rootDir>/examples/move/abstract_iota_accounts/spending_limit/sources/balance_reserve.move#L38-L41
```

**What this does**
- Accepts a `Balance<T>` and adds it to the reserve's balance.
- Increases the total withdrawable amount.
- Separate from the gas balance used for transaction fees.

### Step 6: Ed25519 authenticator with spending limit check

The core authentication logic that validates both signature and spending limit.
```move file=<rootDir>/examples/move/abstract_iota_accounts/spending_limit/sources/spending_limit_account.move#L152-L172
```

**What this does**
- First verifies the Ed25519 signature against the stored public key.
- Then inspects the transaction's PTB commands to find withdrawal calls.
- Calculates the total withdrawal amount across all commands.
- Finally validates that the total doesn't exceed the spending limit.

### Step 7: Look up and calculate withdrawals from PTB

Analyzes the transaction's programmable transaction block to find withdrawal operations.
```move file=<rootDir>/examples/move/abstract_iota_accounts/spending_limit/sources/spending_limit_account.move#L239-L275
```

**What this does**
- Iterates through all commands in the transaction.
- Identifies `withdraw_from_balance_reserve` function calls.
- Extracts the withdrawal amount from each call's arguments.
- Accumulates the total amount to be withdrawn.
- Returns 0 if no withdrawal commands are found.

### Step 8: Validate withdrawal call signature

Helper function to identify valid withdrawal calls targeting this account.
```move file=<rootDir>/examples/move/abstract_iota_accounts/spending_limit/sources/spending_limit_account.move#L276-L298
```

**What this does**
- Checks if the first argument equals the transaction sender (the account itself).
- Verifies the function name is `withdraw_from_balance_reserve`.
- Verifies the module name is `account`.
- Validates the package ID matches the SpendingLimitAccount's package.
- Ensures only legitimate withdrawals from this account are counted.

### Step 9: Execute withdrawal from balance reserve

The actual withdrawal function that transfers funds from the reserve.
```move file=<rootDir>/examples/move/abstract_iota_accounts/spending_limit/sources/spending_limit_account.move#L178-L194
```

**What this does**
- Verifies the amount is within the current spending limit.
- Checks the balance reserve has sufficient funds.
- Withdraws the specified amount from the reserve.
- Decreases the spending limit by the withdrawn amount (one-time use).
- Returns a `Coin<IOTA>` that can be transferred or used.

### Step 10: Authenticate against spending limit

Final validation that the withdrawal amount doesn't exceed the limit.
```move file=<rootDir>/examples/move/abstract_iota_accounts/spending_limit/sources/spending_limit_authentication.move#L59-L65
```

**What this does**
- Retrieves the current spending limit from the account.
- Compares the requested amount against the limit.
- Aborts the transaction with `EOverspend` error if limit is exceeded.
- Allows the transaction to proceed if within limits.

## Verify the result

**Create spending limit account and fund it**

```bash
# Set spending limit (e.g., 999 NANOS maximum per transaction)
export LIMIT=999

# Create account
export PTB_JSON=$(iota client ptb \
--move-call 0x2::authenticator_function::create_auth_function_ref_v1 '<'$PACKAGE_ID'::'$ACCOUNT_MODULE_NAME'::'$ACCOUNT_TYPE_NAME'>' @$METADATA_ID '"'$AUTH_MODULE_NAME'"' '"'$AUTH_FUNCTION_NAME'"' \
--assign ref \
--move-call $PACKAGE_ID::$CREATE_MODULE_NAME::$CREATE_FUNCTION_NAME vector"$SIGN_PUB_KEY_BYTES" $LIMIT ref \
--json)
export ABSTRACTACCOUNT=$(echo $PTB_JSON | jq -r '.objectChanges[] | select(.type == "created" and (.objectType | endswith("::'$ACCOUNT_MODULE_NAME'::'$ACCOUNT_TYPE_NAME'"))) | .objectId')
echo "Account Object ID: $ABSTRACTACCOUNT"

# Fund the balance reserve
iota client ptb \
--split-coins gas "[1000]" \
--assign new_coins \
--move-call $PACKAGE_ID::$CREATE_MODULE_NAME::deposit_to_balance_reserve @$ABSTRACTACCOUNT new_coins
```

**Withdraw funds within spending limit**

```bash
# Create withdrawal transaction (amount must be <= LIMIT)
UNSIGNED_TX_BYTES=$(iota client ptb \
--move-call $PACKAGE_ID::$CREATE_MODULE_NAME::withdraw_from_balance_reserve @$ABSTRACTACCOUNT 998 \
--assign withdrawn_coin \
--transfer-objects "[withdrawn_coin]" @0x0 \
--serialize-unsigned-transaction)
echo "Unsigned TX: $UNSIGNED_TX_BYTES"

# Sign the transaction
# Extract the TX digest that is used by the authenticator to check the signature for the account
TX_DIGEST_HEX=$(iota keytool tx-digest $UNSIGNED_TX_BYTES --json | jq -r '.digestHex')
echo "TX Digest Hex: $TX_DIGEST_HEX"

# Obtain the signature where the message is the TX digest and the signing key is part of the keypair from which the signing address was derived
export IOTA_SIGNATURE_HEX=$(iota keytool sign-raw --address $SIGN_ADDRESS --data $TX_DIGEST_HEX --json | jq -r '.iotaSignature' | base64 -d | od -An -tx1 | tr -d ' \n')
echo "IOTA signature hex: $IOTA_SIGNATURE_HEX"

# Execute with authentication
export SIGNED_TX_BYTES=$(iota client ptb \
--move-call $PACKAGE_ID::$CREATE_MODULE_NAME::withdraw_from_balance_reserve @$ABSTRACTACCOUNT 998 \
--assign withdrawn_coin \
--transfer-objects "[withdrawn_coin]" @0x0 \
--auth-call-args 0x$SIGNATURE_HEX  \
--serialize-signed-transaction)
echo "Signed tx bytes: $SIGNED_TX_BYTES"
iota client execute-combined-signed-tx --signed-tx-bytes $SIGNED_TX_BYTES
```

## Expected Behavior
- Transactions with withdrawal amounts exceeding the spending limit fail with `ESpendingLimitExceeded` error.
- Multiple withdrawal commands in a single transaction are summed and checked against the limit.
- The spending limit decreases by the withdrawn amount after each successful withdrawal.
- Withdrawals from insufficient balance reserves fail with `EInsufficientBalanceReserve`.
- Only valid `withdraw_from_balance_reserve` calls from the correct package are counted.
