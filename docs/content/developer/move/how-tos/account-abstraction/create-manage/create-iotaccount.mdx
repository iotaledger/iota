# Create an Account Using the Builder Pattern

import AccountAbstraction from '@site../content/_snippets/developer/move/aa.mdx';

<AccountAbstraction />

This how-to demonstrates how to use the builder pattern to create and share an account, using `IOTAccount` as an example.

## Example Code

1. Create a builder by passing an authenticator function reference to `builder`.
```move file=<rootDir>/examples/move/abstract_iota_accounts/iotaccount/sources/iotaccount.move#L74-L82
```
2. Optionally attach dynamic fields to the account during build time using `with_field`.
```move file=<rootDir>/examples/move/abstract_iota_accounts/iotaccount/sources/iotaccount.move#L85-L92
```
3. Using dynamic fields we can attach all kinds of additional properties to the account, such as an admin address.
```move file=<rootDir>/examples/move/abstract_iota_accounts/iotaccount/sources/iotaccount.move#L95-L97
```
4. Finalize the account by calling `build`, which validates the authenticator and shares the account object.
```move file=<rootDir>/examples/move/abstract_iota_accounts/iotaccount/sources/iotaccount.move#L101-L113
```
5. Define the authenticator function. The `#[authenticator]` attribute marks a `public`, non-`entry` function as eligible. Its parameters must be, in order: the account reference, any additional read-only inputs, `&AuthContext`, and `&TxContext`. It has no return type — returning normally authorizes the transaction; aborting rejects it. This example verifies an Ed25519 signature over the transaction digest against a public key stored as a dynamic field on the account.
```move file=<rootDir>/examples/move/abstract_iota_accounts/public_key_authentication/sources/public_key_iotaccount.move#L95-L103
```

:::tip Going further with `AuthContext`

The authenticator in step 5 only uses `TxContext` (to access the transaction digest for signature verification). More advanced authenticators can also use `AuthContext` to inspect what the transaction will do — which functions it calls, which objects it involves, and what values it passes — before deciding to authorize it. See [Enforce a Per-Transaction Spending Limit](create-spending-limit-account.mdx) and [Control Which Functions a Key Can Call](function-call-keys.mdx) for examples.

:::
