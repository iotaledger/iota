## About Function Call Keys

Function-call keys let an account owner delegate specific Move function calls to other public keys.
The account's `authenticate` implements two flows: an owner bypass (full power) and a **delegated** flow that only allows a single, pre-approved Move function call per transaction.

## What this example shows

- Create an IOTAccount with an owner public key and an attached FunctionCallKeysStore.
- Grant / revoke a function permission to a delegated public key.
- authenticate that:
    - verifies owner signatures (owner bypass), or
    - verifies delegated signatures and enforces exactly one PTB command whose (package,module,function) is pre-approved.

**What this does**

### Core authenticator — dual flow (owner / function-call-key)

```move file=<rootDir>/examples/move/abstract_iota_accounts/function_call_keys/sources/function_call_keys.move#L111-L164
```

**What this does**
- Owner signature ⇒ immediate allow (no function checks).
- Delegated signature ⇒ require exactly one command and that `(package,module,function)` be allowed for that delegated key.

### Store: FunctionRef type + allow/disallow/is_allowed + extractor

```move file=<rootDir>/examples/move/abstract_iota_accounts/function_call_keys/sources/function_call_keys_store.move#L40-L127
```

**What this does**

- FunctionRef canonicalizes a Move function identity.
- Store maps pub_key -> set(FunctionRef) and provides idempotent allow/disallow checks.
- extract_function_ref converts a PTB MoveCall into the canonical FunctionRef the authenticator checks.

## Verify the result

**Owner grants permission**

```bash
export SIGNED_TX_BYTES=$(iota client ptb \
--move-call $PACKAGE_ID::function_call_keys_store::make_function_ref @0x2 '"'clock'"' '"'timestamp_ms'"' \
--assign function_ref \
--move-call $PACKAGE_ID::$CREATE_MODULE_NAME::grant_permission @$ABSTRACTACCOUNT vector"$FUNCALL_SIGN_PUB_KEY_BYTES" function_ref \
--auth-call-args 0x$OWNER_SIGN_PUB_KEY_HEX 0x$SIGNATURE_HEX  \
--serialize-signed-transaction)
echo "Signed tx bytes: $SIGNED_TX_BYTES"
iota client execute-combined-signed-tx --signed-tx-bytes $SIGNED_TX_BYTES
```

## Expected Behavior
- The account owner can execute any programmable transaction without restriction, while delegated keys are limited to one pre-approved Move function call per transaction.
- Transactions signed by delegated keys succeed only when the called (package, module, function) exists in the on-chain allow-set; otherwise, they are rejected during authentication.
