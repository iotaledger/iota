## About account abstraction

In Account Abstraction, the account itself defines how transactions are authorized.  
For a multisig account, this requires a clear on-chain definition of **who the members are** and **how much approval power each member has**.

This module defines the data structures and logic for managing multisig members and their voting weights.

## What this example shows

This how-to demonstrates the **member management layer** of a dynamic multisig account:

- Defining members with addresses and weights
- Validating multisig configuration (no duplicates, matching inputs)  
- Querying members and total approval weight  
- Providing safe accessors used by the authenticator and transaction logic  

This module contains **no transaction execution logic** and focuses purely on member state.

## Verify the result:

After using this members module:
- Multisig members are stored on-chain with explicit voting weights.
- Invalid multisig configurations are rejected at creation time.
- Approval weight can be calculated deterministically and safely.
- Other modules (transactions, authenticator) can rely on consistent member state.

## Expected Behavior

Only valid multisig member configurations can be created.
All approval and authorization logic built on top of this module operates on a consistent, validated member set.
