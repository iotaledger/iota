pub fn get_owner_objects( &self, owner: Address, cursor: Option<&OwnedObjectCursor>, limit: usize, filter: Option<IotaObjectDataFilter>, max_read: usize, object_store: &dyn ObjectStore, ) -> IotaResult<OwnedObjectsPage>

Objects owned by owner in owner-index order (grouped by type, coins by descending balance, then by id), resolving the fields the index does not store from the object store. The page resumes strictly after cursor, whether or not the object it names is still there.

Returns at most limit objects filter keeps, read from at most max_read index rows, and the cursor to continue from when rows are left: that of the last row read, which need not be on the page. So a page can hold fewer than limit objects, or none, and still have a next one; a full page does not read further to find out whether more objects match, so the last page can be empty.

A filter that pins the object type narrows the scan to that type’s rows; any other filter walks everything owner holds.

pub async fn new( path: PathBuf, historic_db_path: Option<&Path>, registry: &Registry, groups: BTreeSet<IndexGroup>, max_type_length: Option<u64>, epochs_to_retain: Option<u64>, authority_store: &Arc<AuthorityStore>, checkpoint_store: &Arc<CheckpointStore>, cancelled: Arc<AtomicBool>, ) -> Result<Arc<Self>, StorageError>

Opens the store, wiping it and rebuilding the live-state tables first when the indexes are missing or stale.

The history tables are filled by a background replay after this returns; until it finishes, history-backed queries cover a growing range of recent checkpoints. epochs_to_retain also bounds the replay.

Checkpoints executed past the index watermark, whose index commits a power loss lost, are indexed again before this returns; the store is rebuilt instead when their data is gone.

Setting cancelled abandons a rebuild or such a replay running here, failing the open, and stops the background replay. The next open rebuilds the store, or resumes the replay where it stopped.

historic_db_path is the root the history buckets keep their files under, and must be the same on every open of a database; a node names epoch_buckets::HISTORIC_DB_DIR in its live database directory. Unset, the root is that directory in path itself.

pub fn prune(&self, current_epoch: EpochId) -> IotaResult<Option<PrunedBuckets>>

Drops the history of expired epochs, in every history table. Returns the earliest epoch to retain and how many buckets were dropped, None when index pruning is off or there is no history at all.

The retention counts historic epochs on top of the current one: 0 keeps the current epoch only. The newest epoch’s bucket is always kept, since Self::index_checkpoint reads its digests.

A query racing a drop answers without the dropped epoch’s rows. Blocks for as long as the drops take, so callers on an async runtime must use spawn_blocking.

Source

pub fn compact_closed_buckets( &self, current_epoch: EpochId, stop: &dyn Fn() -> bool, ) -> IotaResult<usize>

Compacts the buckets of the epochs below current_epoch that are not compacted yet (see EpochBuckets::compact_closed, which asks stop before each bucket). Blocks while the compactions run, so async callers must use spawn_blocking.

pub fn index_checkpoint(&self, checkpoint: &CheckpointData) -> IotaResult

Builds and stages the index update of one executed checkpoint. Nothing is written until Self::commit_update_for_checkpoint is called. Checkpoints up to the index watermark the store was opened at, and transactions already indexed by the history backfill, are skipped.

Must be called for each checkpoint in sequence order.
