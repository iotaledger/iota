get_denied_certificates
If a transaction digest shows up in this list, when executing such transaction, we will always return ExecutionError::CertificateDenied without executing it (but still do gas smashing). Because this list is not gated by protocol version, there are a few important criteria for adding a digest to this list:
is_any_invariant_violation
Whether kind is an invariant violation of the execution layer or of the Move VM: an internal error, not a failure the transaction caused. A kind wrapped in an ExecutionErrorKind::MoveAuthentication status must be unwrapped first with unwrap_move_authentication_error().
is_cancellation
Whether kind says the execution was canceled rather than failed: canceled at the consensus commit because of shared object congestion, execution worker congestion or unavailable randomness, or denied by is_certificate_denied(). A Move authentication never reports a denial: its input checks skip the deny list, which applies after authentication. A kind wrapped in an ExecutionErrorKind::MoveAuthentication status must be unwrapped first with unwrap_move_authentication_error().

unwrap_move_authentication_error
Returns the error wrapped in an ExecutionErrorKind::MoveAuthentication status, the way the engine reports a failed authentication when the protocol feature flag report_move_authentication_error is on, so the authenticator’s own failure can be matched. Any other kind is returned as it is.
