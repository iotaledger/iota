Expand description

The error check_coin_deny_list_v1 gives with cur_epoch = None when address may not use one of coin_types, or None if it may use them all. Types are checked in sorted order, and for each type a global pause before a denial of address, so the same deny list always gives the same error.

Meant for post-consensus validation, where object_store answers as of a commit: a missing deny-list entry reads as not denied, and any other error of object_store is returned instead of being read as not denied, which would differ between validators.
